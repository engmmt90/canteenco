# Prisma migration policy

Do not hand-write the first production migration.

The initial migration must be generated by Prisma from `prisma/schema.prisma` against a controlled development/staging PostgreSQL database, reviewed, committed, and only then applied to production with `prisma migrate deploy`.

Recommended first-run sequence:

```bash
npm install
npm run env:doctor
npm run schema:invariants
npm run prisma:generate
npm run prisma:migrate -- --name init
git add prisma/migrations
git commit -m "Add initial Prisma migration"
```

Before production:

```bash
NODE_ENV=production npm run migration:preflight
npm run db:deploy
npm run db:smoke
```

The development seed is protected by `ALLOW_DEMO_SEED=true` and must not be run in production.
